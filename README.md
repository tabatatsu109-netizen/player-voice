# Player Voice

選手と指導者の「見えている景色」をつなぐ。

同じ練習について選手と指導者がそれぞれ 1〜10 で評価し、その **認識差** を可視化して
「なぜそう感じたのか」を話し合うきっかけをつくるための Web アプリです。

- 設計の詳細 → [DESIGN.md](DESIGN.md)
- 技術構成：Next.js 15 (App Router) / TypeScript / Tailwind CSS v4 / Recharts / Supabase
- スマートフォン最優先（下部タブ・1タップ入力・入力所要 約1分）

---

## 1. 起動する

```bash
npm install
npm run dev
```

http://localhost:3000 を開き、ログイン画面の
**「デモデータで試す（コード：AOZORA）」** を押すとすぐ中身が見られます。

> 環境変数を設定しない限り **デモモード** で動きます。
> データはブラウザの localStorage に保存され、過去30日分のサンプルが自動生成されます。
> プレゼン当日にネット接続やDBが使えなくても画面を見せられます。

デモデータを作り直したいときは、ブラウザの開発者ツールで
`localStorage.removeItem('player-voice-db-v2')` を実行して再読み込みしてください。

---

## 2. Supabase につないで実運用する

1. [supabase.com](https://supabase.com) でプロジェクトを作る
2. SQL Editor に [`supabase/schema.sql`](supabase/schema.sql) を貼って実行
   （末尾の初期データのチーム名・コード・名簿を自分のチームに書き換えてから実行）
3. `.env.local` を作る

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...
```

4. `npm run dev` を再起動

環境変数が入っていれば、同じコードのまま Supabase 側を読み書きします
（画面上部の「デモモード」の帯が消えます）。

## 3. 公開する（GitHub Pages）

```bash
npm run build
```

`out/` に静的ファイルが出力されます。リポジトリ名のサブディレクトリに置く場合は
`.env.local` に以下を追加してからビルドしてください。

```
NEXT_PUBLIC_BASE_PATH=/リポジトリ名
```

## 4. チームでの運用手順

| いつ | だれが | なにを |
|---|---|---|
| 練習後すぐ | 選手 | スマホで `/player` を開き、8項目タップ＋任意コメント（約1分） |
| その日のうち | 指導者 | `/coach` で同じ練習を評価。**選手の回答を見る前に**入力する |
| 翌日のミーティング前 | 指導者 | `/dashboard` と `/compare` で認識差の大きい項目を確認 |
| 週1回 | 全員 | 差が大きかった項目を1つ選び、5分だけ話す |
| 期間終了後 | 管理者 | `/export` から CSV を出して前半／後半を比較 |

指導者が選手の回答を見る前に入力することが重要です。
先に見てしまうと「合わせにいった数字」になり、認識差が測れなくなります。

## 5. 画面

| パス | 画面 | 見られる人 |
|---|---|---|
| `/` | ログイン（チームコード → 立場 → 名前） | 全員 |
| `/player` | 選手入力 | 選手 |
| `/coach` | 指導者入力 | 指導者・管理者 |
| `/dashboard` | チームダッシュボード | 指導者・管理者 |
| `/compare` | 日別比較 | 指導者・管理者 |
| `/players` | 個人推移 | 指導者・管理者 |
| `/export` | 研究用CSV出力 | 指導者・管理者 |

選手のログインでは他人のデータを読み込まず、個人データ画面にも入れません。

## 6. 認識差の計算

```
認識差 = 選手平均 − 指導者評価
```

絶対値が大きいほど認識のズレが大きいと判断します。

| 差 | 判定 |
|---|---|
| 0.0〜0.9 | ほぼ一致 |
| 1.0〜1.9 | 少しズレ |
| 2.0〜2.9 | ズレが大きい |
| 3.0以上 | 要対話 |

同じ「差3.0」でも項目ごとに意味が違うため、画面には必ず日本語の読み取りと
話し合いのヒントを添えています（定義は [`src/lib/metrics.ts`](src/lib/metrics.ts)）。

指導者が未入力の日は 0 で埋めず「未比較」として集計から除外します。

### 画面の言葉と、研究の言葉の対応

画面には高校生と指導者がそのまま読める言葉を出し、CSV の見出しには研究で使う言葉を残しています。
発表で説明するときは、この対応表を手元に置いてください。

| 画面に出る言葉 | 研究・CSV での言葉 | DBのカラム |
|---|---|---|
| 見え方のちがい | 認識差 | （計算値） |
| 人によるちがい | 標準偏差 (SD) | （計算値） |
| 体調 | 体調・コンディション | condition |
| つかれ具合 | 疲労度 | fatigue |
| 練習のきつさ | 練習強度 | intensity |
| がんばり具合 | 練習への取り組み | effort |
| 目的が伝わったか | 練習目的の理解 | purpose_understanding |
| 戦術のわかりやすさ | 戦術理解 | tactical_understanding |
| チームの雰囲気 | チームの雰囲気 | team_mood |
| 縮まった分 | 改善量（前半−後半） | （計算値） |

判定の言葉も同じ考え方でやさしくしています。
だいたい同じ（0.0〜0.9）／少しちがう（1.0〜1.9）／けっこうちがう（2.0〜2.9）／話し合おう（3.0以上）。

## 7. このシステムの立場

監督の判断を否定するためでも、選手の意見をすべて通すためでもありません。
**お互いの見え方の違いを可視化して、話し合う材料をつくる**ためのものです。
そのため、順位付けや優劣の表示は意図的に入れていません。
